# MyApp — Agent Guide

Entrypoint for AI coding agents (`CLAUDE.md` is a one-line pointer importing this file). Production-ready Phoenix 1.8 + Ash 3 template with OIDC/Magic Link authentication, i18n (en/de/fr), Oban job processing, and daisyUI theming.

**Read [docs/CODEBASE.md](docs/CODEBASE.md) before any non-trivial change** — it is the authoritative technical reference for the domain layer, the component system, Cinder tables, auth, and i18n. This file only keeps the essentials.

**Read [docs/PROJECT.md](docs/PROJECT.md) for product context** — what this application is for, its audiences, and its vocabulary. (In the pristine template it is a placeholder to fill in when a real product grows out of the template.)

**Consult [docs/usage-rules.md](docs/usage-rules.md) freely when working with dependencies** — it is autogenerated (untracked) by `usage_rules` and links to each package's usage rules straight from its authors. It also documents `mix usage_rules.docs` / `mix usage_rules.search_docs` for looking up dependency documentation. If it is missing or stale (e.g., after dependency changes), regenerate it with `mix usage_rules.sync` — the same command also rebuilds the `ash-framework` and `phoenix-framework` skills under `.claude/skills/`.

## Stack

Elixir 1.19 / OTP 28 · Phoenix 1.8 + LiveView 1.1 · Ash 3 (AshPostgres, AshAuthentication, AshOban, AshStateMachine) · PostgreSQL · Oban · Tailwind CSS v4 + daisyUI (bundled with bun, no node/npm) · Tabler Icons · Cinder tables · Gettext + ex_cldr (en/de/fr) · Sentry.

## Commands

```bash
mix setup              # Initial setup (deps, DB, assets, seeds)
mix ash.setup          # Create DB + run Ash migrations
mix test               # Run tests (auto-runs ash.setup)
mix precommit          # Full check: gettext, format, lint, test
mix lint               # CI linting: format, gettext, credo, sobelow, migration check
mix usage_rules.sync   # Regenerate docs/usage-rules.md + agent skills from deps
```

Always run `mix precommit` when done with all changes and fix any pending issues.

## Key conventions

- Ash resources are the source of truth for data; use `mix ash.codegen <name>` after resource changes.
- Use `:req` (Req) for HTTP requests — avoid :httpoison, :tesla, :httpc.
- **Never hand-roll UI primitives** — use the core component system (`lib/my_app_web/components/core/`): `<.icon>`, `<.button>`, `<.badge>` are auto-imported; everything else via facade aliases (`alias MyAppWeb.Components.Core` then `<Core.Inputs.text ...>`). Full reference and extension pattern in [docs/CODEBASE.md](docs/CODEBASE.md).
- Components wrap daisyUI classes; class names must be complete literals (Tailwind's scanner cannot see `"btn-#{color}"`).
- Domain constants use `MyApp.Shared.EnumData` (`Ash.Type.Enum` with per-value data + gettext labels).
- Tables: `Cinder.collection` with the daisyUI theme from `components/cinder/`.
- Begin LiveView templates with `<Layouts.app flash={@flash} ...>`; admin routes live behind the `EnsureAdmin` plug (`/oban`, `/dev`).
- Tailwind v4: no `tailwind.config.js`, never `@apply`; only the `app.js` / `app.css` bundles exist — no external `<script>`/`<link>` tags.
- A hook shared by several components or subclassed by another lives in `assets/js/hooks/` and is registered in `app.ts` (`phx-hook="Dialog"`); a hook belonging to one component's markup stays colocated (`phx-hook=".Foo"`). A colocated hook that only re-exports a class from `assets/js/` is misplaced.
- Colocated hooks are TypeScript: `<script :type={ColocatedHook} name=".Foo" extension="ts">` with a class `extends ViewHook` from `phoenix_live_view` (typed from the hex dependency's own bundled types, resolved through the `assets/package.json` workspace that links `deps/*` into `assets/node_modules`) as the default export. Never hand-format them — `mix format` runs prettier over every `<script>` body.
- UI/UX: produce world-class designs with clean typography, spacing, and layout balance; add subtle micro-interactions (hover effects, smooth transitions, loading states).
